Originless

Person 1 uploads the file. Person 2 gets it without asking Person 1 again.

The name a file answers to is decided by its own bytes — the CID. That's why anyone who has it can serve it, anyone can verify it, and nobody has to "host" it.

Person 1

Uploader

Keeps their own copy. Serves the file when asked — but with nothing pinned their node is a temp landing spot, not an archive.

POST /up — bytes → CID
Landing zone

Originless node

Stores the blocks (unpinned). Uses DHT to announce CID. GC may drop it — by design.

GET /cid — or any gateway
Person 2

Fetcher

Needs only the CID. No account, no token, no request to Person 1. Bytes verified against the hash on arrival.

Person 1 side
Nothing pinned Blocks are dropped when they stop being useful to *this* node. Content stays alive on the network as long as someone holds & re-uploads it.
The file's only identity
CID = hash of the bytes Bafk…9d2c Same name on every node, verified on arrival. Change one bit, the CID changes.
Person 2 side
Verified, not trusted Fetch from Person 1's node, another node, or a public gateway — the bytes have to hash to the CID to be accepted.
